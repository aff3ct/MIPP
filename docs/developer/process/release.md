# Release

A MIPP release is an annotated Git tag `vX.Y.Z` on `develop` (`v2.0.0` to `v2.1.0` so far). The version only exists in the tag: the headers carry no version macro. Pushing the tag to the public GitHub repository publishes the release.

---

## 1. What the Tag Triggers

On GitHub, a `v*` tag runs the `generation` job, then two jobs that only run on tags ([Continuous Integration](ci.md#2-github-actions)):

- `deploy-docs` builds the site with `mkdocs build --strict` and deploys it to GitHub Pages (<https://aff3ct.github.io/MIPP/>);
- `release` creates the GitHub release of the tag, with two archives of the generated `include/` (`mipp-vX.Y.Z-headers.zip` and `mipp-vX.Y.Z-headers.tar.gz`) and release notes generated by GitHub from the history.

The archives contain the headers generated with `--simd-ext sse avx avx512 rvv neon scalar --granularity fine`: SVE is not included.

On GitLab, the tag runs the usual pipeline.

---

## 2. Checklist

1. **The GitLab pipeline is green** on the commit to release: GitHub does not build or test anything.
2. **The documentation builds in strict mode.** The site is only deployed if `mkdocs build --strict` succeeds on GitHub. Check it locally first:
    ```bash
    (cd generator && ./gen_mipp_docs.py)
    mkdocs build --strict
    ```
3. **Tag and push.** Create an annotated tag (signed with `-s` if you sign your commits) and push it to both repositories, `develop` first:
    ```bash
    git tag -a vX.Y.Z -m "MIPP vX.Y.Z"
    git push <gitlab-remote> develop vX.Y.Z
    git push <github-remote> develop vX.Y.Z
    ```
4. **Check the publication**: the GitHub Actions run of the tag, the two archives attached to the release, and the deployed site.
5. **Edit the release notes** on GitHub if the generated ones are not enough (highlights, breaking changes).

If `deploy-docs` fails, the release and its archives are still created, but the site is not updated. A re-run of the workflow uses the tagged commit: it only helps for transient failures. A documentation error needs a fix on `develop` and a new patch tag.
